# Phone evidence between recurrent updates

This development study uses the existing 926-trial tuning split, the released T15 features and the official checkpoint. The previous validation report has been inspected. No new holdout is claimed. Existing models, logits and the v1 and v2 freezes stay in their original run directories.

## Comparisons fixed before training

1. Keep the five-layer GRU at 80 ms and predict the intervening 40 ms emission from the preceding state and newly available features. Compare with an 80 ms GRU adaptation and a GRU adapted to update every 40 ms. Start all three from the same official checkpoint. Use the same training order, tune neither the endpoint nor the decoder separately, and report each arm.
2. At 40 ms output intervals, compare 10-, 14- and 20-bin input patches with 20 ms acquired features. Separately compare a 280 ms patch on a 20 ms grid, means of pairs on a 40 ms grid and a 10 ms grid made by repeating each available sample. The last condition tests representation and alignment. The public B2T trials contain no independent samples inside a released bin.
3. Compare the official Gaussian with a channel-wise trainable, transient-sensitive filter. Test a low-rank change to the input transform and a learned mixture around softsign. The earlier multiview head study remains the evidence for raw/light/official residual fusion.
4. Compare a small causal dilated convolutional encoder that represents patch level and recent changes, trained on allowed training trials, with the recurrent models. Count inherited weights and distinguish distillation and adaptation from training from random initialization.
5. Run a two-by-two frozen-checkpoint diagnostic. Either advance the recurrent state every 80 ms or every 40 ms. Emit scores on either grid by repeating slow logits or selecting the even fast logits. Check the unchanged greedy sequence after repetition, word and phone edit counts, and blank occupancy.
6. Test the lexical decoder on posterior emissions and hard phone paths. Use reference phones only as an evaluation intervention. Keep them out of fitting and deployment. Report where the phone path loses information and whether accounting for word-edit risk helps.
7. On the laptop, compare CPU FP32 and dynamic INT8 on released intracortical features. Keep the lexical search fixed within that comparison. Distinguish final text latency, phone cadence, and prefix replay. The project has no paired consumer EEG/text acquisition to validate a scalp EEG decoder.

The planned training endpoint is 2,048 single-trial updates per condition. Each training admission requires a 900-second real-data pilot with decoding and checkpoint I/O. The runner records forecasts, resource stops and actual counts. Use separate Slurm jobs so interrupted conditions can be recovered independently. Prefer the two normal A100s for the primary rate conditions. Standby work may lose its allocation.

Use repaired Flashlight beam 50, KenLM train-only three-gram, LM weight 2 and the existing text normalization for the encoder comparison. For timing, run three warm passes of the same 24 tuning trials stratified by original duration, batch size one, with a persistent model and decoder. Time feature read through final text with transfers and CUDA synchronization. Keep timing on one A100 class with four CPUs. Report full tuning word and phone edit totals, paired uncertainty and peak memory separately from timing. A new trained phone step is an opportunity to update the posterior, not a promise of a new word every 40 ms.
